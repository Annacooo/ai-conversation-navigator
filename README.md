# AI Conversation Navigator 🧭

一个给 AI 对话网页用的小工具扩展：导出对话、跳转到某一问、快速回到上一问/下一问。

它最开始是为 ChatGPT 长对话做的，因为 AI 回答太长，翻回上一个问题真的很烦。现在它已经改成更通用的版本，会尝试适配常见 AI 对话工具。

> ✨ 当前版本：`0.5.5`
>
> 🚧 状态：开发中，适合本地安装测试；还没有发布到 Chrome Web Store / Edge Add-ons。

## 功能 ✨

- 🧲 竖向悬浮工具条，尽量不挡正文。
- 🖱️ 顶部 `Q/A` 区域可以拖动，位置会自动记住。
- 🫥 点击顶部 `Q/A` 区域可以收起工具条。
- ↩️ 收起后保留小条，点击小条可以展开。
- ⬆️ 使用 `↑` / `↓` 图标跳到上一问或下一问。
- 📍 点击当前问数，例如 `1/4`，打开滚动列表并跳到指定问题。
- 📤 点击“导出”后再选择导出内容和格式。
- 支持导出：
  - 全部问答
  - 仅提问
  - 仅回答
- 支持格式：
  - Markdown
  - JSON
  - TXT
- 支持中文和英文浏览器语言。
- 会过滤页面按钮和纯 UI 文案，避免把“展开/收起”之类的按钮识别成提问。
- 对虚拟滚动页面做了缓存，尽量避免总问数忽多忽少。

## 适配范围 🌐

扩展不是只为 ChatGPT 写死的。它会在 HTTPS 页面加载，但只在常见 AI 站点，或者检测到对话消息结构时显示工具条。

## 安装 🛠️

### 本地安装

1. 下载或克隆这个仓库。
2. 打开浏览器扩展管理页：
   - Chrome：`chrome://extensions`
   - Edge：`edge://extensions`
3. 开启“开发者模式”。
4. 点击“加载已解压的扩展程序”。
5. 选择本项目文件夹。
6. 打开或重新载入 AI 对话页面。

### 更新本地版本

如果已经安装过旧版本：

1. 打开扩展管理页。
2. 找到这个扩展。
3. 点击“重新加载”。
4. 回到 AI 对话页面并重新载入页面。

只点扩展重新加载还不够，因为旧页面里可能仍然跑着旧版脚本。

## 使用 🚀

- 拖动顶部 `Q/A` 区域：移动工具条。
- 点击顶部 `Q/A` 区域：收起工具条。
- 点击收起后的小条：展开工具条。
- 点击 `↑`：跳到上一问。
- 点击 `↓`：跳到下一问。
- 点击 `1/4` 这样的问数按钮：打开问题列表。
- 点击“导出”：打开导出面板。
- 点击“重扫”：重新扫描当前页面里的对话内容。

快捷键：

- `Alt + ↑`：上一问
- `Alt + ↓`：下一问

## 导出格式 📦

### Markdown

适合保存、阅读、丢进笔记软件。

### JSON

适合后续处理、脚本分析、再导入别的工具。

### TXT

适合最简单的纯文本保存。

## 隐私 🔒

这个扩展只在浏览器本地运行。

- 不上传对话内容。
- 不请求任何第三方服务器。
- 不收集分析数据。
- 不需要登录扩展账号。
- 导出文件直接在本机生成。

为了兼容更多 AI 工具，扩展的匹配范围是 `https://*/*`。这会让浏览器显示更宽泛的权限提示，但扩展会尽量只在 AI 对话页面或检测到对话结构时显示工具条。

## 已知问题和限制 ⚠️

这些问题不是藏着不说，而是当前版本真实存在的边界：

### 1. 有些 AI 网站可能识别不准

每个 AI 网站的页面结构都不一样，而且经常改版。扩展现在是通过网页里的消息角色、元素属性、常见类名来判断“谁是用户、谁是 AI”。如果某个网站完全不用可识别的 DOM 结构，可能无法正确识别。

### 2. 虚拟滚动仍然可能影响完整导出

很多长对话页面会使用虚拟滚动：离屏太远的消息会临时从页面里移除。扩展已经做了“已发现问题缓存”，所以问数不会轻易从 4 问掉成 3 问。

但如果某些消息从来没有被浏览器渲染出来过，扩展也无法凭空读取。遇到超长对话时，建议先滚动一遍，让页面把内容加载出来，再点“重扫”和“导出”。

### 3. 跳转依赖页面滚动容器

扩展会尝试找到真实滚动容器，而不是只滚动 `window`。这已经比早期版本稳定很多，但如果某个网站使用非常特殊的滚动实现、Shadow DOM、Canvas 或内部路由容器，跳转可能仍然不完美。

### 4. 浏览器商店未发布

当前只是本地开发者模式安装版本，还没有上架 Chrome Web Store 或 Edge Add-ons。别人使用时需要手动加载已解压扩展。

### 5. Firefox 未完整测试

代码里兼容了 `chrome.i18n` 和 `browser.i18n`，但当前主要测试目标是 Chrome / Edge 的 Manifest V3。

### 6. 通用权限看起来会比较大

为了支持多个 AI 对话工具，`manifest.json` 使用了：

```json
"matches": ["https://*/*"]
```

这可能会让用户看到“可读取网站数据”之类的浏览器权限提示。扩展本身没有网络请求，也不会上传内容。如果后续想更保守，可以把匹配范围改成一组固定 AI 站点域名。

## 常见问题 ❓

### 为什么工具条没有出现？

可能原因：

- 页面还没有加载完。
- 当前网站不在内置 AI 站点列表里。
- 页面没有可识别的消息结构。
- 扩展没有重新加载。
- 页面还在运行旧版脚本。

可以尝试：

1. 重新载入页面。
2. 点击扩展管理页里的“重新加载”。
3. 回到页面后再重新载入一次。

### 为什么总问数不对？

可能是虚拟滚动、页面懒加载或 AI 网站结构特殊导致的。

可以尝试：

1. 从上到下滚动一遍对话。
2. 点击“重扫”。
3. 再打开问题列表。

### 为什么导出的内容不完整？

扩展只能导出当前页面已经加载/识别过的内容。超长对话建议先滚动一遍，让页面内容被加载出来。

### 为什么某个按钮也被识别成问题？

扩展已经过滤了常见 UI 文案，比如“展开/收起”。但不同网站的按钮文案可能不一样。如果发现误识别，可以提交 issue，附上：

- 网站地址
- 截图
- 被误识别的文字
- 浏览器名称和版本

## 开发 🧑‍💻

项目结构：

```text
.
├── manifest.json
├── content.js
├── style.css
├── PRIVACY.md
├── README.md
└── _locales
    ├── en
    │   └── messages.json
    └── zh_CN
        └── messages.json
```

主要文件：

- `content.js`：扫描消息、跳转、导出、拖动、收起展开。
- `style.css`：工具条和弹出面板样式。
- `_locales/*/messages.json`：中英文文案。
- `manifest.json`：扩展配置。

## 本地检查 ✅

可以用 Node 检查脚本语法：

```bash
node --check content.js
```

也建议确认 JSON 文件能正常解析：

```bash
node -e "JSON.parse(require('fs').readFileSync('manifest.json','utf8')); console.log('ok')"
```

## 发布建议 🚢

建议先做 GitHub 发布，不急着上浏览器商店。

建议步骤：

1. 新建 GitHub 仓库：`ai-conversation-navigator`
2. 上传这些文件。
3. 后续补一张截图到 `assets/screenshot.png`。
4. 创建一个 GitHub Release，例如 `v0.5.5`。
5. 打包 zip，供用户下载后本地安装。

打包时不要包含：

- `.git`
- `.DS_Store`
- `Thumbs.db`
- 旧的 zip / crx 文件
